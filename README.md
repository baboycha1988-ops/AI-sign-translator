# AI Sign Translator

Система перевода жестового языка в текст (субтитры) на основе компьютерного зрения. Проект готовится к республиканскому конкурсу «Илм — фурӯғи маърифат» (номинация «Зеҳни сунъӣ ва барномасозӣ»).

> **Статус: ранний прототип (этапы 1–7 из 12).** Работающего переводчика жестов ещё нет.
> Поддержка таджикского жестового языка **не заявляется**: для неё нет проверенного датасета.
> Подробное состояние, что проверено и что нет: [STATUS.md](STATUS.md).

## Что есть сейчас

| Часть | Где | Состояние |
|---|---|---|
| Схема БД PostgreSQL (32 таблицы, триггеры, функции) | `db/` | Структура проверена скриптом; **на реальном PostgreSQL не запускалась** |
| Ядро API: вход, права, словарь, предложения жестов, решение «распознан / неоднозначно / неизвестно» | `apps/api/` | Ядро покрыто тестами; HTTP-слой FastAPI **не запускался** |
| ML: признаки, разбиение по людям, базовая модель, калибровка, метрики, контроль качества образцов | `packages/ml/` | Тесты на синтетических данных (проверяют конвейер, **не точность**) |
| Нейросеть PyTorch, извлечение ключевых точек MediaPipe | `packages/ml/signml/` | **Только написаны, не запускались** |
| Интерфейс (8 экранов, 3 языка, камера) | `apps/web-prototype/` | Прототип без распознавания; не проверен в браузере |
| Протокол сбора датасета | `docs/dataset-protocol.md` | Черновик, нужна проверка юристом и специалистами |

Не сделано: репозиторий на PostgreSQL, остальные группы API, WebSocket, веб-клиент Next.js, админ-панель, обучение на реальных данных, платежи, документация для конкурса.

## Принципы проекта
- Видео обрабатывается на устройстве; видео обычных пользователей не сохраняется.
- Образцы датасета — только с письменным согласием участника; согласие можно отозвать.
- Неизвестный жест никогда не превращается в случайное слово.
- Точность и преимущества не заявляются без реальных экспериментов.

## Быстрый старт (проверка тестов)
Нужен Python 3.12.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
bash scripts/run_tests.sh
```

Скрипт печатает реальный результат каждого набора тестов и завершается с ошибкой, если что-то упало.

### База данных (нужен Docker и psql)
```bash
cp .env.example .env        # впишите длинный случайный POSTGRES_PASSWORD
./scripts/db_verify.sh      # чистый PostgreSQL 16 + миграция + SQL-тесты
```

### Запуск API
```bash
cd apps/api
export JWT_SECRET="$(python3 -c 'import secrets; print(secrets.token_urlsafe(48))')"
export DEV_AUTO_VERIFY=1    # только для разработки: подтверждение e-mail ещё не реализовано
uvicorn app.main:app --reload
# документация: http://127.0.0.1:8000/docs
```
Данные API пока хранятся в памяти и пропадают при перезапуске.

## Структура
```
apps/api/             FastAPI: auth, словарь, предложения жестов, правила публикации модели
apps/web-prototype/   HTML-прототип интерфейса
packages/ml/signml/   признаки, разбиение по людям, baseline, калибровка, QC, PyTorch-модель
packages/spec/        эталон признаков для будущего JS-порта (golden_features.json)
db/                   миграции и SQL-тесты ограничений
docs/                 протокол датасета, ER-диаграмма (генерируется scripts/gen_er.py)
scripts/              проверки и вспомогательные скрипты
infra/                docker-compose для локального PostgreSQL
.github/workflows/    автоматический запуск тестов на GitHub
```

## Опциональные зависимости
- `packages/ml/requirements-extract.txt` — OpenCV и MediaPipe (нужны ещё файлы моделей `.task`, их нет в git).
- `packages/ml/requirements-torch.txt` — PyTorch и ONNX для нейросетевой модели.

## Что нельзя коммитить
Видео, записи людей, ключевые точки реальных участников, обученные модели, `.env` и любые ключи. Это закрыто в `.gitignore`; перед публикацией запускается `scripts/check_repo.py`.
