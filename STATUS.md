# AI Sign Translator — состояние проекта (для передачи другому разработчику или ИИ)

Дата: 20.11.2026. Автор ТЗ: один участник, без GPU, без команды. Цель: конкурс «Илм — фурӯғи маърифат» (номинация «Зеҳни сунъӣ ва барномасозӣ»), ориентир на 2027 год после официального объявления сроков.

## Что известно о конкурсе (Низомнома 2026, №АП-950)
- Оцениваются новые компьютерные/мобильные программы и программы управления ИИ; максимум 100 баллов.
- Баллы дают: госрегистрация информационного ресурса (5), свидетельство Минкультуры (5), внедрение, экономический эффект, новизна, коммерциализация. Без свидетельств максимум 80.
- 1 место только при ≥75 баллов. В финале есть тест Наццентра тестирования (<50% — не допускают ко второй части) и защита алгоритма перед жюри.
- Положение 2027 года ещё не объявлено; требования нужно перепроверить.

## Структура
- `db/migrations/0001_initial.sql` — схема PostgreSQL (32 таблицы, 17 из ТЗ + модуль 20), триггеры, функции.
- `db/tests/constraints.sql` — тесты ограничений БД. `scripts/db_verify.sh` — запуск в Docker.
- `apps/api` — FastAPI: вход/регистрация/refresh, права, ограничение запросов, проверка загрузок, словарь (поиск, слияние дублей), предложения жестов с полным жизненным циклом (проверка, сбор образцов, готовность, обучение, условия публикации), решение «распознан / неоднозначно / неизвестно». Хранилище пока в памяти.
- `packages/ml/signml` — признаки (спецификация), разбиение по людям, базовая модель (sklearn), калибровка порогов, метрики, QC образцов, извлечение MediaPipe, нейросеть PyTorch.
- `packages/spec/golden_features.json` — эталон признаков для JS-порта.
- `apps/web-prototype/index.html` — интерфейс (опубликован как артефакт), 8 экранов, 3 языка, без распознавания.
- `docs/dataset-protocol.md`, `docs/er-diagram.md` (генерируется `scripts/gen_er.py`).

## Известные отклонения и ограничения
- Пароли: scrypt (stdlib) вместо Argon2id из архитектуры; формат хэша хранит параметры, переход возможен.
- Хранилище API сейчас в памяти (`repo.py`); реализация на PostgreSQL не написана.
- Подтверждение e-mail не реализовано (флаг `DEV_AUTO_VERIFY=1` для разработки).
- Не написаны: остальные группы API (словарь, история, предложения, датасеты, модели, подписки, админ, WebSocket), веб-клиент на Next.js, ONNX-инференс в браузере, 3D-аватар, режим «Речь → Жесты», платежи, админ-панель, CI/CD.
- Базовая модель на синтетике: при ложном принятии неизвестных 0% правильно принимается только ~29% известных. Слабое место, нужно улучшать на реальных данных.
- Поддержка таджикского жестового языка НЕ заявляется: `sign_languages.evidence_status = 'no_verified_dataset'`; в БД нельзя сделать модель текущей, пока язык не `validated`.
- Цены Premium и все пороги (≥3 человека, ≥15 образцов, пороги QC, пороги отказа) — стартовые значения, не результаты исследований.
- Тексты на таджикском в интерфейсе написаны ИИ и требуют проверки носителем.
